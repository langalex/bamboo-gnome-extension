# AGENTS.md — bamboo_gnome_extension

Guidance for AI coding agents working in this repository. Read this before
making changes, and follow the existing conventions — they are deliberate,
not accidental.

## Project overview

A **GNOME Shell 51 extension** (GJS) that shows BambooHR clock-in status and
today's logged time in the top bar. Written in **TypeScript**, bundled with
**esbuild** to single-file **ESM** for GJS 1.72+ (GJS supports native ESM
only — there is no CommonJS at runtime).

- Runtime target: GNOME Shell 51, GJS (Soup 3, GTK4/Adw, GObjects)
- Dev tooling: Node.js ≥ 18 + npm + TypeScript (dev-time only)

## Commands

| Command              | Purpose                                                                                                     |
| -------------------- | ----------------------------------------------------------------------------------------------------------- |
| `npm run check`      | Type-check (`tsc --noEmit`) for both main and test tsconfigs — run this after any change                    |
| `npm test`           | Unit tests (vitest, under Node)                                                                             |
| `npm run test:watch` | Unit tests in watch mode                                                                                    |
| `npm run test:gjs`   | GJS smoke test for the compiled status logic (needs `gjs` installed)                                        |
| `npm run build`      | Bundle `src/` → `dist/` (`extension.js`, `prefs.js`, `status-test.js`)                                      |
| `npm run watch`      | Rebuild bundles on change                                                                                   |
| `./install.sh`       | Build + stage into `~/.local/share/gnome-shell/extensions/bamboo-timesheet@user/`, compile GSettings schema |

Typical loop: edit → `npm run check` → `npm test` → `npm run build`.
`./install.sh` + `gnome-extensions enable bamboo-timesheet@user` to try it in
a real shell (reload with `Alt+F2` → `r` on X11, or log out/in on Wayland).

## Structure

```
src/
├── extension.ts        # GNOME Shell entry point: panel indicator, popup, lifecycle
├── prefs.ts            # GTK4/Adw preferences dialog
├── lib/
│   ├── bamboohr.ts     # BambooHR API client (Soup 3, Basic auth, typed errors)
│   ├── status.ts       # PURE logic: summarize entries, totals, formatting (no GI imports)
│   ├── settings.ts     # Typed GSettings wrapper
│   └── types.ts        # API request/response shapes
└── types/gi-ambient.d.ts
test/
├── mocks/              # stubs for gi:// modules (vitest aliases them, see vitest.config.ts)
├── bamboohr.test.ts
├── settings.test.ts
└── status.test.ts
schemas/                # GSettings schema XML
build.mjs               # esbuild bundler (also emits the `export const meta` block)
install.sh, metadata.json, stylesheet.css
```

Key architectural rule: **`src/lib/status.ts` is pure logic with no GObject /
GI imports.** Keep it that way — it runs unchanged under Node (vitest) and
under GJS (`test:gjs` via the standalone `status-test.js` bundle). Anything
touching the GNOME Shell or GTK APIs stays in `extension.ts` / `prefs.ts`.

## Conventions and gotchas

- **GJS imports:** use bare GI specifiers like `import GLib from "gi://GLib"`,
  `import Soup from "gi://Soup?version=3.0"`; internal modules use `.js`
  extensions (`import type { ClockEntry } from "./types.js"`). esbuild keeps
  `gi:*`, `resource://*`, `gettext`, and `cairo` external — never bundle them.
- **Never edit anything in `dist/`** — it is fully regenerated by
  `npm run build` (which also appends `export const meta` from
  `metadata.json`). Don't add post-build patching of `dist/extension.js` to build.mjs.
- **TypeScript is strict**; `npm run check` must pass with zero errors before
  you consider work done.
- **GNOME extension lifecycle:** anything created in `extension.ts`'s `enable()`
  (signals, GLib timeouts, Soup sessions, panel indicators) must be cleaned up
  in `disable()`. Persisted state is not stored locally — status always comes
  from the API.
- **Timezones:** "today" is computed per entry using the entry's own IANA
  timezone (see `isToday`), not the host's, to avoid midnight-rollover bugs.
  Don't change this to use the local timezone. Tests pin `TZ=UTC` for
  determinism.
- **API details** (endpoints, auth, error handling, known 401/403/409/422
  behaviors) are documented in `PLAN.md` §2 — consult it before touching
  `src/lib/bamboohr.ts`.
- **UUID** is `bamboo-timesheet@user`; settings schema
  `org.gnome.shell.extensions.bamboo-timesheet`. Keep `metadata.json`,
  `install.sh`, and the schema filename in sync if it ever changes.
- **Secrets:** the BambooHR API key lives in GSettings (user-entered via
  prefs). Never hardcode it anywhere, including tests.

## Testing

- Tests live in `test/*.test.ts` and run under vitest in plain Node; GJS-only
  modules are faked via aliases in `vitest.config.ts` → hand-written stubs in
  `test/mocks/`. If you add a new `gi://` import to shared lib code, add a
  mock (or keep the module out of unit-tested code).
- Prefer extending the pure-logic tests in `test/status.test.ts` over adding
  GJS-dependent tests.
- `npm run test:gjs` verifies the bundled `status-test.js` actually runs under
  GJS — useful after changes to `src/lib/status.ts` or the build config.
